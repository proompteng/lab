# Penpot

The official Penpot Helm chart (1.12.0 / Penpot 2.19.1) runs in the dedicated
`penpot` namespace, reconciled by the platform ApplicationSet.

- Private HTTPS: <https://penpot.ide-newton.ts.net> (Tailscale ingress).
- PostgreSQL: dedicated `penpot-db` CloudNativePG cluster, with two instances
  and retained Ceph RBD storage. The generated `penpot-db-app` Secret supplies
  application credentials; never store its content in Git.
- Assets: retained 20Gi Ceph RBD PVC. Back up both PostgreSQL and assets.
- Valkey: isolated, in-namespace, ephemeral cache and collaboration pub/sub.
- Session key: `penpot-api-key` generated by External Secrets once and retained.
- MCP: enabled in Penpot and routed through the frontend; restrict clients to
  the tailnet and use normal Penpot permissions.
- Registration: enabled for initial account creation on the private tailnet;
  review access policy once accounts are created.
- Frontend: upstream Nginx `worker_processes auto` counts all 384 logical CPUs
  exposed by Turin, causing startup OOMs even with a 2Gi limit. A small init
  container prepares a four-worker copy of the upstream template; keep its
  image version aligned with the Helm chart on upgrades.

Deployment checks:

1. Render: `kustomize build --enable-helm argocd/applications/penpot`.
2. Confirm `Application/penpot` is Synced/Healthy at the merged Git revision.
3. Confirm the CNPG cluster is healthy, ExternalSecret Ready, Valkey ready, and
   Penpot backend/frontend/exporter/MCP Deployments available.
4. Confirm `Ingress/penpot` is provisioned by Tailscale, then open the URL from
   a connected tailnet device and validate account creation and design editing.

Rollback by reverting the manifest/chart revision and reconciling ArgoCD;
retain the database PVCs, asset PVC, and application signing key.
